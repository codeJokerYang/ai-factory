# 网页指令工作流

用户从本地网页提交需求和逐行硬性要求，原始文本进入 ProjectState，所有 Agent 调用与修复保留此文本。模型生成的摘要不能替代原始指令。

## 验收条件

- 输入为空、过长、非法 JSON 或并发提交时明确返回错误。
- 方案未经批准不执行 Builder；审批拒绝结束当前任务。
- 每次构建使用独立生成目录，完整运行报告持久化到 `.factory/runs/<id>/report.json`。
- 安全扫描在 npm 之前运行，禁止生成可覆盖执行配置的文件；安装禁用生命周期脚本。
- 编译修复后必须对最终代码重新审查。构建、审查、安全、指令核对、预览有任一未通过，不得批准 Gate 2。
- 原始指令整体核对；R1…Rn 逐项返回代码证据，缺失/重复编号拒绝解析，虚构代码证据改判不确定。
- 网页可以查看进度、审批、缺失项与报告下载，刷新后继续查询。

## 编辑式网页界面

- 冷灰全屏首屏、原创透明冰质主视觉与大字叠层；同一素材提供四种视角，不声称实时 3D。
- 工作台采用开放双栏，窄屏改为单列。需求与审批默认展示可读文字，日志、实施与技术细节按需展开。
- 视角按钮支持鼠标、触摸、方向键及 Home/End；当前状态通过 `aria-pressed` 提示。
- 桌面指针视差最大水平 10px、垂直 8px、旋转 1deg；触摸和 reduced-motion 模式关闭视差，后者也关闭过渡与入场动画。
- 静态图片仅开放固定 `/assets/glacier.png`，保持本机 Host 限制；不开放目录与用户文件。
- 浏览器检查覆盖 1440、1024、768、390 宽度、指令提交、方案展示、拒绝重试及报告下载。测试 API 数据仅存在于自动化的独立浏览器中。

## 运行限制

代码核对不是运行时业务验收。无容器隔离、无持久化任务恢复、无 DAG 增量执行、无自动发布。每次拒绝后通过新的请求重新运行；不会自动声称已完成上一条失败指令。
