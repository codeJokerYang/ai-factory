# 长期项目与增量版本（P0-1）

## 已实现行为

- `project_id` 继续标识单次执行，新增 `workspace_id` 标识长期项目；旧任务首次迁移各自成为独立项目。
- 新项目可关联客户名称。这是业务标签，不是多用户认证或权限隔离。
- 修改通过 `base_version` 引用已结束任务，沿用原需求、客户、源码和依赖，追加修改及硬性要求。有可用版本时，只允许以当前版本为基础；旧版本需先显式恢复。
- 首次生成仍返回完整文件；修改、编译修复和审查修订返回带原 SHA-256 的 `changes`。未提及文件逐字保留；删除需原哈希，不允许删除主页面。路径越界、大小写冲突、重复项、过期哈希拒绝。
- 修改写入新目录；检查及人工验收全部通过才更新当前可用版本。不自动发布。
- 完成归档不可覆盖；恢复只更新引用并记审计事件。项目有运行任务时禁止恢复。
- 本地任务弹窗提供版本、源码差异、继续修改与恢复入口。长差异有截断标识，完整源码可下载。
- 源码以归档为准。原目录存在时核对归档特性文件，发现手改或缺失就阻止继续修改；原目录已删除时可从归档生成候选目录。

## 接口

| 接口 | 功能 |
|---|---|
| POST `/api/jobs` | 原参数兼容；可选 `client_name`、`base_version` |
| GET `/api/projects` | 项目概览 |
| GET `/api/projects/:id` | 项目、版本列表与切换记录 |
| GET `/api/jobs/:id/changes` | 与基准版本的源码差异 |
| POST `/api/projects/:id/restore` | `{ "version": "任务ID" }` 切换到已验收版本 |

接口沿用本机 Host 与会话校验；写接口检查 Origin。读取差异和恢复引用不调用模型。继续修改提交才调用模型，仍需方案和预览审批。

## 数据与限制

新增 projects、versions、project_events 表，保留 tasks 原文；初始化只迁移未关联任务，重复启动不重置版本选择。旧报告需具备全部检查及逐项证据才计为可用版本。

仍是单后端进程，不支持多人并发编辑；中断任务不自动执行。增量修改是文件差异协议，不是 DAG 执行或行级补丁。特性源码外的脚手架由现有生成器提供；尚无外部代码库导入、手改合并、生成器版本锁定或生产部署。

## 验证

`tests/test_projects.py` 覆盖迁移、重启、三次更新、失败与过期候选、质量证据、归档不可变、显式删除、路径/哈希攻击、手改检测、API 和完整修改流水线。浏览器脚本覆盖版本、差异及携带基准版本提交。

流水线回归使用模拟模型、构建及预览验证编排和文件保留；不代表真实模型修改质量或生成网站业务功能已验证。
