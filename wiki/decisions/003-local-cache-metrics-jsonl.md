# ADR-003: 缓存指标使用本地版本化 JSONL

- **状态**: 已采纳
- **日期**: 2026-07-20
- **决策者**: 项目维护者 / Codex

---

## 背景

L2 与 L3 已能确定性命中并注入 Builder，但没有证据说明命中频率、回退效果或案例质量变化。
项目当前是本地优先 CLI，引入远程遥测、数据库或新的 LLM 统计调用会增加成本、隐私面和运维负担。

## 决策

采用两层观测：

1. 单次 lookup 作为 typed `CacheLookup` 进入 `ProjectState`，保证 Sequential/LangGraph 编排均可见。
2. Build CLI 将去业务化事件追加到本地 `.factory/cache-metrics.jsonl`，使用版本化 JSONL，
   提供离线汇总命令。

指标只记录来源、受控或哈希 ID、context 大小和质量门计数。token 使用明确标注的字符估算；
不把“注入了多少 context”伪装成供应商账单节省。

## 考虑的选项

### 选项 A: 只打印日志

- 优点: 实现最少。
- 缺点: 无法跨运行聚合，趋势不可复现。

### 选项 B: 本地 JSONL（采用）

- 优点: 追加简单、容错读取、可审计、无需服务依赖。
- 缺点: v1 不支持多进程写锁；需要主动运行汇总命令。

### 选项 C: 远程遥测服务

- 优点: 可集中展示和告警。
- 缺点: 引入认证、网络、隐私和部署面，超出当前本地优先边界。

## 后果

### 正面影响

- 命中率和回退效果有稳定口径。
- 指标损坏或写入失败不会影响 Builder 与 Gate 2。
- 不保存原始需求、prompt、代码或可读 L3 项目名。

### 负面影响 / 风险

- token 仅为相对估算，不能替代供应商 usage。
- `.factory/` 是本地状态，不适合天然跨机器聚合。
- JSONL 单进程追加满足当前 CLI，但未来并发 worker 需要文件锁或独立事件存储。

## 后续条件

只有在出现并发构建或团队级集中报表需求时，才迁移到带幂等事件 ID 的数据库/遥测后端；
迁移时继续保留 `schema_version` 和无业务文本约束。
