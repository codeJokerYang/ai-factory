# ADR-004: 生成 UI 使用确定性视觉基线与 advisory 静态审计

- **状态**: 已采纳
- **日期**: 2026-08-14
- **决策者**: 项目维护者 / Codex

---

## 背景

仅要求 Builder “使用 Tailwind”只能保证技术栈一致，不能稳定保证视觉层级、响应式、交互状态
或无障碍。完全依赖一次 LLM 生成和 Gate 2 人工截图，会让低级 UI 问题发现过晚且重复发生。

## 决策

采用三层 UI 质量机制：

1. `scaffold.py` 确定性提供语义设计令牌、基础 UI 类和全局可访问性回退。
2. Builder 与 Reviewer 共用同一组 UI 质量目标，但不引入新的模型调用。
3. Builder 输出后运行静态审计，把 typed 报告传到 CLI 与 Gate 2；发现仅 advisory。

## 选择理由

- 确定性 CSS 能保证所有生成应用都有一致下限，且不消耗 token。
- Prompt 负责产品语境、内容与组合，适合模型判断。
- 静态审计适合捕获语义标签、断点、label、alt 和错误交互元素等机械退化。
- Gate 2 仍保留最终视觉裁决，避免把正则审计误当成浏览器或设计评审。

## 考虑的替代方案

### 引入完整组件库

能快速提升一致性，但增加依赖、版本和主题定制成本，也违反当前最小依赖白名单。

### 增加独立 UI LLM Reviewer

可能更懂视觉语境，但增加调用成本和不稳定性；现有 Reviewer 已可覆盖主观部分。

### 静态审计阻断构建

规则简单直接，但会因合法的非典型设计产生误阻断；因此 v1 只进入 warning 与 Gate 2 摘要。

## 后果

- 新应用默认视觉质量和键盘可用性提高。
- Builder 输出可能新增 UI warning，但不会影响 `next build` 成功语义。
- 未来如果引入浏览器级 axe/视觉回归，可继续复用 `UIQualityReport`，逐步替换粗粒度正则规则。
